# Parley — лента покупателей и активов

Готовый отдельный C++20-проект: Telegram-бот и база из 100 пар с 400 текстами А1/А2/Б1/Б2. Внешние AI-сервисы не используются. Доступны лента, избранное, прогресс, отмена последнего решения, исходные цитаты и выбор сценария обращения.

## Быстрый запуск на Ubuntu

1. Распакуйте архив **в отдельную папку**. Это полная замена приложения; не накладывайте `src` поверх старого проекта с автоматическим `GLOB_RECURSE`.
2. Скопируйте в эту папку ваш прежний `.env`. Обязательны только `BOT_TOKEN` и `ALLOWED_USERS`. Старые ключи Polza, Checko и DaData можно оставить: бот их не использует.
3. Из папки проекта выполните:

```bash
bash start.sh --check
```

Первый запуск соберёт проект. При отсутствии зависимостей скрипт установит пакеты через `apt`, для чего может потребоваться `sudo`. Проверка базы выполняется без подключения к Telegram.

4. Остановите прежний процесс бота с тем же токеном и запустите новый:

```bash
bash start.sh
```

Откройте тот же бот в Telegram и отправьте `/start`. Токен и Telegram ID бота остаются прежними. Если старое приложение работает под systemd, сначала остановите именно его службу; название зависит от вашего сервера. Два приложения с одним токеном одновременно запускать нельзя: Telegram вернёт ошибку 409.

Проверена сборка на Ubuntu 24.04 x86-64 с GCC 13.3. Требования к исходной сборке: C++20, CMake 3.20+, libcurl, SQLite3 и nlohmann-json 3.10+. Готовый Linux-бинарник не включён, чтобы сборка использовала библиотеки именно вашего сервера.

## ENV

```dotenv
BOT_TOKEN=ваш_прежний_токен
ALLOWED_USERS=123456789, 987654321
MATCHES_DB=data/matches.sqlite3
```

`MATCHES_DB` необязателен. Относительный путь считается от папки `.env`. Переменные процесса имеют приоритет над `.env`. Поддержаны пробелы в списке ID, кавычки, CRLF, UTF-8 BOM и `export`. Пустой список пользователей запрещён. ID неавторизованного пользователя бот покажет ему без раскрытия базы.

Не добавляйте значения токена в командную строку. Не выкладывайте `.env` в git. В архиве находится только пример `.env.mock`.

## Интерфейс

| Действие | Результат |
| --- | --- |
| 🃏 Лента | Первая непросмотренная пара, от лучших оценок к меньшим |
| ❤️ Подходит | Сохраняет пару, показывает контекст и отдельное готовое обращение покупателю |
| 👎 Пропустить | Сохраняет решение и открывает следующую пару |
| 🔎 Подробнее | Полные основания, расхождения, исходные цитаты, даты и ссылки |
| ↩️ Отменить решение | Отменяет последнее решение и возвращает его карточку |
| ❤️ Избранное | Сохранённые пары, по пять на страницу, с доступом ко всем текстам |
| ✉️ Покупателю / Продавцу | Выдаёт заранее подготовленный текст выбранного формата |
| 🔄 Сценарий обращения | Выбор А1/А2 под запрос покупателя или Б1/Б2 под предложение продавца |
| 📊 Прогресс | Просмотрено, подходит, пропущено, осталось |

Команды: `/start`, `/feed`, `/favorites`, `/progress`, `/undo`, `/help`.

После лайка сценарий по умолчанию определяется более поздней публикацией пары. Его можно переключить; выбор сохраняется отдельно для каждой пары и пользователя. А1/Б1 имеют одинаковое тело по согласованным шаблонам. Б2 предназначен для уточнения недостающих данных.

Служебный блок и обращение отправляются отдельными сообщениями. Скопируйте само обращение стандартным действием Telegram. Длинный текст разбивается по строкам с учётом UTF-16; при объединении частей исходный текст полностью восстанавливается. Сообщения людям бот сам не отправляет. Работа — только в личном чате с разрешёнными пользователями.

## Данные и сохранность решений

`data/parley_matches_100.sqlite3` — исходная подготовленная база. На первом обычном запуске создаётся **рабочая копия** `data/matches.sqlite3`. Если рабочая база уже есть, она используется без перезаписи. Для подключения другой копии задайте `MATCHES_DB`.

В рабочую базу добавляются четыре служебные таблицы: `bot_history`, `bot_modes`, `bot_offsets`, `bot_undo_updates`. Исходные пары и тексты не меняются. Реакции находятся в `review_decisions`, ключ — пользователь и пара. Отмена, решения и история выполняются транзакциями. Кнопки содержат устойчивые ID пар, а не номера в ленте. Повторный лайк или запоздалый пропуск уже обработанной пары не перезаписывает решение.

При сетевом сбое после лайка пара остаётся в избранном, где можно повторно получить текст. Доставка сообщения Telegram не является транзакцией SQLite: возможный неопределённый результат сетевого запроса не приводит к откату сохранённого лайка.

Бот восстанавливает long polling после временных ошибок; учитывает Telegram `retry_after`, экранирует HTML и ограничивает частоту сообщений. При неверном токене или одновременном запуске другого бота завершается с ошибкой. Локальная блокировка дополнительно запрещает два процесса с одной рабочей базой. На запуске включается long polling с отключением webhook без удаления ожидающих обновлений.

Для резервной копии остановите приложение и скопируйте `data/matches.sqlite3`. Не заменяйте этот файл чистой базой при обновлении кода. При остановленном боте используется один SQLite-файл без WAL. Файл `.lock` не содержит данных и после остановки не удерживает блокировку.

В подборке 33 запроса, 51 актив, 100 пар; 56 пар включают публикации августа 2026. Последнее сообщение экспорта — 16.08.2026, сентября нет. Проценты обозначают редакционную оценку соответствия, а не вероятность сделки. Цены и сведения взяты из переписки; актуальность не подтверждена. Даты пересылок относятся к архивному чату. Ссылки на закрытый чат доступны его участникам. Подробная документация данных сохранена в `metadata`, ключ `README`.

## Локально на Windows

Используйте Visual Studio 2022 с компонентом C++ и CMake, а также ваш vcpkg. Проект содержит `vcpkg.json`.

В Developer PowerShell из папки проекта:

```powershell
$env:VCPKG_ROOT = 'C:\dev\vcpkg'
.\start.ps1
```

Замените путь на ваш. Рядом должен лежать прежний `.env`. Скрипт соберёт Release и запустит приложение. В CLion можно открыть `CMakeLists.txt` и указать toolchain vcpkg; рабочая папка запуска — корень проекта. Windows-сборка в среде подготовки архива не запускалась.

## Автозапуск на сервере

В `deploy/parley.service` есть образец systemd для `/opt/parley` и системного пользователя `parley`. Перед установкой замените `User`, `Group`, `WorkingDirectory`, `ExecStart` под ваше размещение. Пользователь службы должен читать `.env` и иметь право записи в каталог рабочей базы. Сначала соберите и проверьте приложение вручную; служба запускает уже собранный бинарник.

После настройки файла и остановки прежней службы:

```bash
sudo cp deploy/parley.service /etc/systemd/system/parley.service
sudo systemctl daemon-reload
sudo systemctl enable --now parley
sudo systemctl status parley
journalctl -u parley -f
```

## Проверки

```bash
sudo apt-get install -y libgtest-dev
cmake -S . -B build-tests -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build-tests --parallel 2
ctest --test-dir build-tests --output-on-failure
```

Тесты используют временные копии базы и имитацию Telegram. Они не требуют токена и никому ничего не отправляют. Проверяются изоляция пользователей, перезапуск, повторные нажатия, отмена, все четыре шаблона, избранное, ошибки отправки, доступ и длина сообщений. Проверка реального подключения к Telegram потребует вашего ENV на сервере.

## Структура кода

`model` — данные пары; `storage` — SQLite и транзакции; `ui` — текст карточек и клавиатуры; `bot` — сценарии и long polling; `http` — Telegram API через libcurl; `config` — ENV; `system` — блокировка процесса и остановка.

Из донорского проекта сохранены подход к long polling, имена конфигурации и разделение `ParleyBot` / `ConversationController` / `MessageManager`; RAII-инициализация curl адаптирована из его HTTP-слоя. Для этой версии Telegram API вызывается напрямую через libcurl. Зависимости аналитики компаний, PDF, TgBot и AI не требуются. Идентификаторы английские, ошибки русские, `.hpp` и `.cpp` разделены; исходники форматируются приложенным `.clang-format`.
